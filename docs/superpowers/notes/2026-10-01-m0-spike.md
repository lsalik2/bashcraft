# M0 spike: synchronous segment execution on 26.3

**Approach tested:** clear `Commands.CURRENT_EXECUTION_CONTEXT` around `performPrefixedCommand`, so the
segment gets its own top-level `ExecutionContext` and runs to completion before the call returns.
Result via `CommandSourceStack.withCallback`, feedback via `withSource`.

| Q | Question | Result |
|---|---|---|
| Q1 | Result known before returning (player via /execute) | PASS |
| Q2 | Success feedback captured | PASS |
| Q3 | Failure reported as failure + message | PASS |
| Q4 | Works when the outer command runs inside a function | PASS (ran; but no feedback captured — see finding 1) |
| Q5 | Nested function inside the segment completes | PASS (block set; but no result callback — see finding 2) |
| Q6 | Works from a command block | PASS |

Raw probes:
```
Q1 Probe[command=setblock 0 120 0 minecraft:stone, callbackFired=true, success=true, result=1, messages=[commands.setblock.success]]
Q3 Probe[command=setblock 0 120 0 minecraft:stone, callbackFired=true, success=false, result=0, messages=[Could not set the block]]
Q4 Probe[command=setblock 1 120 0 minecraft:stone, callbackFired=true, success=true, result=1, messages=[]]
Q5 Probe[command=function bashcraft-test:mark, callbackFired=false, success=false, result=0, messages=[commands.function.scheduled.single]]
Q5 block set: true
Q6 Probe[command=setblock 3 120 0 minecraft:stone, callbackFired=true, success=true, result=1, messages=[commands.setblock.success]]
```

**Findings**

1. Inside a function the invoking stack is silent (`FunctionCommand` runs bodies with `withSuppressedOutput()`),
   and `sendSuccess` drops messages before they reach any `CommandSource`. Q4 captured nothing. Piping inside
   functions therefore needs the planned `CommandSourceStackMixin` (capture at the head of `sendSuccess`).
2. `/function` only reports a result through the callback when the function executes `return`. A plain function
   runs to completion but the callback never fires (Q5 `callbackFired=false`). Treating "no callback" as failure
   would make `sh function setup && say done` never run `say done`.

**Decision:** Approach confirmed — continue with Task 3. Task 8 adds: a segment whose callback never fired counts
as success (result 0) unless it sent a failure message; failures are tracked by `TeeSource` via the mixin.
